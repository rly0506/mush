## 1. 目标与价值

当前看板是"功能堆叠型"单页：10 个平级视图、侧栏三栏常驻、D 编号/Goal 编号/合同术语直接暴露、中英混排、空态文案各自为政。owner 的判断是**对齐成熟 agent 产品（codex / claude code / zcode）的简洁**——那些产品的共性是：**一条主对话流是唯一主角，其余一切按需展开**。

价值：商业化门面。试用者打开 30 秒内应能理解"我在这和 agent 说话、派活、看结果"，而不是面对一张驾驶舱。

## 2. 现状痛点清单（体检实证）

1. 信息过载：首屏同时呈现对话区+活动线+犬队+预算四栏；
2. 视图平级失衡：「对话工坊/任务池/调度/工作流/犬队天梯/效能大屏/事件链/预算/carveouts/审批」10 个 tab 平铺，主轴（对话）不突出；
3. 术语泄漏：effort/XHIGH/carveout/stream_id/SUPERSEDED/D 编号直出界面；
4. 双口径数据并存易混淆（侧栏"暂无台账" vs 预算视图 ccusage 有数）；
5. 小瑕疵：favicon 404；workspace 徽标显示「服务 cwd」而非目录名；
6. 空态文案不统一、部分视图无可用空态引导。

## 3. 目标信息架构（三层收敛）

```
L1 主界面（默认，90% 时间停留）：单一对话流
  - 头犬对话为主轴（思考折叠/工具活动/正文三段式，与 GOAL-075 对齐）
  - 任务进展以"轻量卡片"内嵌对话流（派发卡/审批卡已有雏形，统一视觉）
  - 顶栏只留：会话选择 · workspace · 头犬徽章 · 一个「⚙」入口
L2 工作台（次级，点按进入）：任务池 + 派发表单 合并为一个"工作台"
  - 任务泳道保留但视觉降权；派发表单收进抽屉/对话框
L3 控制台（低频，收纳页）：犬队·预算·审计·事件链·carveouts·辩论等
  - 单一「控制台」入口下的分区页签，不再占主导航
```

导航从 10 tab 收敛为 **3 入口**（对话 / 工作台 / 控制台）。

## 4. 核心架构设计

- `src/web/page.ts` [REWRITE] — 页面骨架按 L1/L2/L3 重排；现有 DOM/JS 为行为参考，视觉与结构重写

### 4.2 设计约束（宪法级，交接必读）

- 密钥红线不变；暗色主题令牌化保留（雪橇队母题可保留也可重定，由执行模型提案、owner 定夺）；
- 所有数据来自既有端点；发现数据缺口记缺陷，不在前端造数据。

### 4.3 术语表（人话原则 D36 升级版，执行时全站套用）
| 现术语 | 界面用语 |

| effort/XHIGH | **保留模型原生梯度原文**（low/medium/high/…，不译中文；仅去掉 XHIGH 这类内部代号直出） |
