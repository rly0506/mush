# GOAL-077: 小白级 harness 接入与零门槛上手 (Novice-Grade Harness & Zero-Threshold Onboarding)

- 状态：`PROPOSED`（owner 2026-08-24 定调："接入的 harness 对小白门槛太高；商业化面向普罗大众必须 0 阈值"；点名 workbuddy 等基础工具）
- 来源：owner 商业化判断 + WorkBuddy 对标调研（2026-08-24）
- 优先级：高（商业化的产品形态前提；与 GOAL-076 前端重铸互为表里——076 管"看得懂"，本 Goal 管"用得着"）
- 依赖：GOAL-076 P1（信息架构收敛先行，否则新用户仍面对驾驶舱）

## 1. 目标与价值

现状的每个接入通道都要求用户理解"harness/合同/探针/effort/工作区"等概念，且需要本地 CLI 凭据（cc-switch profile、API key、npm 全局包）——这是极客配置，不是大众产品。对标 **WorkBuddy**（腾讯桌面 AI Agent 工作台）：自然语言下达任务 → 自动规划拆解 → 多 Agent 并行执行 → 交付文档/图表产物，主打"零门槛开箱即用，普通职场人无需技术背景"。

价值：mush 的差异化恰恰在于**多犬编排 + 本地文件面治理 + 审计留痕**（WorkBuddy 们没有的），但被过高的入口门槛锁死。打通"小白也能用"后，编排能力才构成卖点。

## 2. 三层门槛拆解与对策

| 层 | 现状门槛 | 目标形态 |
|---|---|---|
| 安装层 | Node + npm 全局包 + 各家 CLI + 凭据配置 | 一键安装包（RM-010 桌面打包已有基线）内置引导；缺什么装什么，全程图形化 |
| 凭据层 | 用户自备各家 API key / cc-switch | 内置免费档先跑通（opencode free 已实证 $0 可用）；付费档引导式接入（粘贴 key 即测即用，含余额/连通性反馈） |
| 认知层 | 必须理解犬只/harness/派发/流 | **单一自然语言入口**：用户只说"帮我做 X"，头犬自动选犬编排；harness 概念对小白完全隐藏（进阶模式才暴露） |

## 3. 核心架构设计

### 3.1 模块与文件变更清单
- `src/adapters/contract.ts` [MODIFY] — 合同增加 `audience: 'novice' | 'pro'` 分级标记（UI 按此决定是否向用户暴露该通道细节）
- `src/web/server.ts`（发现层）[MODIFY] — 新增消费级通道适配位：WorkBuddy 类桌面 Agent 若提供本地协议（CLI/HTTP），按既有 T1/pi-rpc 同模式接入；具体候选需实测调研（见验收）
- `src/web/page.ts` [MODIFY] — 新手引导流（首次启动三步：选语言→给一个任务样例→跑通第一单）；专业术语全部收进「进阶模式」开关
- `src/core/onboarding.ts` [NEW] — 引导状态机（检测凭据/通道健康 → 推荐最小可用路径）

### 3.2 关键接口与数据契约
- 名册视图新增 `audience` 与 `ready_for_novice: boolean`（安装+凭据+探针三条件聚合）；前端据此渲染「立即可用」vs「需要配置」
- 首启引导 API：`GET /api/onboarding/status` + `POST /api/onboarding/advance`

## 4. 验收规格

- [ ] 新建自动化测试 `tests/g077-onboarding.test.ts`：引导状态机、novice/pro 分级过滤、免费档零凭据首跑路径
- [ ] 端到端（小白剧本）：一台干净 Windows → 安装包 → 5 分钟内不接触任何术语完成一次真实任务并看到结果
- [ ] WorkBuddy 及同类（千问办公 Agent 等）接入可行性实测报告：有无本地可编程入口、许可条款是否允许第三方编排——**结论写入本文档附录后再施工对应适配器**
- [ ] 严格遵守宪法红线：零凭据泄露（引导流程永不回显 key）、零外部 CDN、对外暴露需 owner 明确开启（门 4）

## 5. 边界与风险

- WorkBuddy 为腾讯闭源商业产品，"接入"若指其作为执行端，须以其实际开放的本地协议为准；若无可编程入口，则本 Goal 的落点转为**产品形态对标**（自然语言单入口 + 自动编排）而非通道接入——两种路线 owner 定夺后更新本节。
