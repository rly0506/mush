## 1. 目标与价值

mush 防跑飞很强（熔断/预算门/超时治理），但**没有角色对「任务到底完没完成」负责**：组件各自为政，受阻是终态，头犬宣称完成即完成，用户面对「迟迟无法完成」只能猜。本 Goal 设立任务监理（Mission Supervisor）：不干活，只对一个问题的闭环负责——**这个任务还活着吗？卡住了我怎么办？** 滞了就按阶梯干预，完成要核验，受阻能自解冻，完成率上屏成可盯的数字。

价值：任务完成率从「感觉」变「指标」；无人值守的信任来源——监理是用户不在场时的那双眼睛。

## 2. 核心架构设计

### 2.1 干预阶梯（核心状态机）

```
心跳正常 → [N 分钟无实质进展] 滞判
  ├─ 一级：换道重试（子级级直换，走 080 故障转移，不惊动头犬）
  ├─ 二级：失败现场打包（哪个子级/什么错/试过什么）喂头犬走计划门 amend 重排
  ├─ 三级：升级提问——向 owner 提具体可答的问题（经聊天流 + 滞涩队列按需唤醒），
  │        而非笼统「受阻」
  └─ 全阶梯失败：任务受阻留痕；探针恢复后监理自动解冻转就绪（受阻从终态变暂态）
```

诚实边界：监理兜**基础设施性**卡死；**模型能力性**绕路（规划烂/任务描述不清）无法代劳，但通过三级干预把黑箱变白箱。

### 2.2 模块与文件变更清单
- `src/core/mission-supervisor.ts` [NEW] — 心跳监听 + 滞判 + 干预阶梯状态机 + 受阻自解冻；每步干预留痕可回放
- `src/web/dispatch.ts` [MODIFY] — 进展信号埋点（子级完成事件/工具活动/token 流心跳上报监理）
- `src/web/chat.ts` [MODIFY] — 二级干预的失败现场注入头犬 charter（复用 G075 计划门 amend 通道）；三级提问帧
- 完成核验 [MODIFY] — 头犬宣称完成 ≠ DONE：G028 独立验证犬对完工声明做 GoD 对照核验，通过才落 DONE
- `src/web/page.ts` [MODIFY] — 洞察区新增：任务完成率 / 平均完工时长 / 滞涩归因分布（一等公民指标）
- `src/core/circuit-breaker.ts` [VERIFY] — 协同边界：熔断停机时监理不得绕保险丝（停机即三级干预升级，不许偷跑）
